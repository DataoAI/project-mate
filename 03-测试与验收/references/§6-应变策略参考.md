# §6 应变策略参考

> 用途：03-Step 2生成初验风险预判报告时参考
> 说明：验收应变策略不是"风险应对"，而是面对甲方、监理、相关方时可能出现的各种问题，提前想好怎么应对

---

## 场景一：甲方说"这个功能不符合要求"

| 甲方说 | 可能的真实原因 | 应变策略 |
|:------|:------------|:--------|
| "这个界面不是我想要的" | 需求理解偏差，或甲方看到实物后想法变了 | 拿出需求确认书，指出"这是当时双方确认的"；如果确实有偏差，区分是"变更"还是"遗漏" |
| "这个功能我之前提过" | 需求遗漏，或甲方记错了 | 查看需求偏差分析表，确认是否在合同范围内；如果在范围内无记录→说明当时未确认，可作为变更处理 |
| "这个功能跟招标文件不一样" | 招标文件写的和做的不一致 | 拿出需求偏差分析表，说明"偏差在哪里，当时已确认" |
| "整体效果还行，但细节还要改" | 甲方想借机多要东西 | 区分"必须改的"和"可以后改的"；必须改的→确认是否超出范围，走变更；可以后改的→列入运维期处理 |

## 场景二：监理说"文档不全"

| 监理说 | 应变策略 |
|:------|:--------|
| "验收文档不齐全" | 拿出验收清单，逐项对照，缺什么补什么 |
| "测试报告不规范" | 按监理要求的格式重新整理 |
| "你们没有按照流程走" | 查看过程文档，如周报、会议纪要、变更记录，证明流程合规 |
| "这个交付物不符合标准" | 确认标准是什么，差异在哪；如果是标准理解不同→协商；如果是确实没做到→制定整改计划 |

## 场景三：相关方质疑

| 相关方说 | 应变策略 |
|:---------|:--------|
| "项目延期了，怎么处理" | 拿出变更跟踪表，说明延期原因（需求变更、技术难点等） |
| "预算超了吧" | 拿出合同范围基线，确认哪些在原范围内、哪些是新增变更 |
| "质量不行" | 拿出测试报告、验收记录，证明已通过测试 |

## 场景四：验收会上的突发情况

| 突发情况 | 应变策略 |
|:--------|:--------|
| 甲方临时提新需求 | 记录到变更跟踪表，说明"这个不在本次验收范围内，作为变更处理" |
| 甲方领导不了解情况 | 准备项目整体汇报材料，让领导快速了解 |
| 多方意见不一致 | 先搁置争议，明确哪些已达成一致，哪些需要进一步讨论 |
| 对方要求降价 | 拿出合同和变更记录，说明"所有变更都有据可查" |
