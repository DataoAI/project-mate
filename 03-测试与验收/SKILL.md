# 03-测试与验收

> 版本：v1.0 | 日期：2026-08-01
> 定位：技术团队测试完成后，项目经理组织初验、终验，管理各相关方，确保项目顺利收尾
> 上游依赖：02b过程管理数据、技术团队测试报告
> 下游输出：初验报告、终验报告、终验确认书、移交清单

---

## 角色定位

**你的身份**：验收管理专员——跟踪测试进度，组织初验和终验，预判验收风险，准备应变策略。

测试本身是技术团队的事，项目经理不负责具体测试。但项目经理需要**掌握测试状态**，并根据测试结果决策是否推进。

## 执行步骤

### Step 1：分析测试数据

技术团队提交测试报告后，AI分析：

```
测试通过率：[XX]%（[XX]/[XX]用例通过）
遗留问题：[XX]个（高[XX]个、中[XX]个、低[XX]个）
需求覆盖率：[XX]%（需求规格说明书中的功能已覆盖）
关键路径：核心功能测试全部通过/未全部通过
```

AI输出测试状态摘要，格式见📂§1-测试状态摘要模板。用户根据测试状态决定是否推进到初验。

### Step 2：生成初验风险预判报告

AI根据前序所有数据，识别本次初验可能被质疑的地方：

```
初验风险预判报告：
- 需求偏差分析表中标注的"偏差项" → 可能被甲方质疑
- 变更跟踪表中未完成的变更 → 可能被监理质疑
- 测试报告中遗留的中级问题 → 可能被甲方质疑质量
- 里程碑计划中延期的节点 → 可能被相关方质疑进度
```

针对每个潜在问题，AI给出应对策略，格式见📂§6-应变策略参考。

### Step 3：组织初验会

用户组织初验，甲方确认系统功能。会后把初验结果发给AI，AI整理成初验报告，格式见📂§2-初验报告模板。

初验通过后，系统进入正式运行期。遗留问题记录到📂§5-遗留问题跟踪表模板。

### Step 4：终验

**① AI核查终验条件**
- 初验后的遗留问题是否全部解决？
- 系统运行期内是否稳定？
- 所有变更是否已确认？
- 文档是否齐全？

**② AI准备终验材料**
AI整理所有阶段文档，打包成终验材料包。

**③ 组织终验会**
用户组织终验，甲方确认并签字。AI输出终验报告，格式见📂§3-终验报告模板。甲方签字后输出终验确认书，格式见📂§4-终验确认书模板。

**④ 终验通过后，进入04-收尾验收阶段**
