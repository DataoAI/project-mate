**六个阶段，覆盖项目全生命周期：**

| 阶段 | 做什么 | 关键产出 |
|:----|:------|:--------|
| 00 项目启动建档 | 收集资料，AI理解项目背景 | 项目章程、认知摘要、启动会方案 |
| 00.1 知识库建立 | 历史资料入库，RAG可检索 | Chroma知识库 |
| 01 需求管理 | 持续输入，AI分析整合，偏差分析 | 需求规格书、偏差分析表、变更跟踪表 |
| 02 技术交底与过程管理 | 技术交底 + 持续过程管理 | 交底确认书、周报、风险登记册、质量跟踪 |
| 03 测试与验收 | 测试分析，初验→终验，应变策略 | 初验报告、终验确认书 |
| 04 收尾验收 | 移交、绩效评价、复盘、归档、关闭 | 移交确认书、项目档案、关闭确认书 |

> 其中 02b 过程管理是持续性阶段，从需求确认后启动，一直运行到项目结束。

## 痛点 / Problem

一个项目经理的日常，被什么占据了？

- 整理会议纪要，提取需求点，一条条录进需求表
- 每周把进度、风险、成本、资源整合成周报
- 验收前翻遍所有文档，找"甲方可能质疑的地方"
- 变更来了，先翻合同范围，判断是变更还是遗漏
- 复盘时，从几十份文档里翻数据、对时间线

这些工作占了PM大约 **70% 的时间**，却只用了 **30% 的脑力**。

真正值钱的判断、决策、协调、预判——反而没时间做。

**这就是工具化的悖论：**
工具把流程理顺了，却把项目经理变成了"填表的人"。

## 与传统工具的区别 / vs Traditional Tools

```
传统项目管理工具（飞书/Jira/Trello）：
  人是操作者，工具是记录者
  工具解决"条理性"，不解决"思考"
  用了工具，PM还是得自己填表、自己想、自己写

项目搭子（ProjectMate）：
  AI是操作者，人是决策者
  AI处理"琐碎"，人专注"判断"
  AI做填表/整理/整合/预判，PM做决策/协调/权衡
```

**一句话：传统工具让人干活，项目搭子替人干活，人做决策。**

## 人机分工 / Division of Labor

| PM的琐碎工作 | 传统方式 | 项目搭子 |
|:------------|:--------|:--------|
| 整理会议纪要→需求点 | 逐条手动提取，约2小时 | AI自动提取+整合，约5分钟 |
| 每周周报 | 翻进度/风险/成本表，约3小时 | AI自动汇总+偏差分析，约10分钟 |
| 验收前预判甲方质疑点 | 凭经验翻文档，凭感觉猜 | AI基于全量数据预判，列出应对策略 |
| 变更判断 | 翻合同找范围，判断变更还是遗漏 | AI先查合同基线+偏差表，给判断建议 |
| 复盘数据汇总 | 从几十份文档翻数据 | AI自动汇总全项目数据 |

## 15年经验去哪了 / Where the 15 Years Went

传统项目管理的经验，靠老PM口头传承——"遇到这种情况你就这么办"。

但AI不知道这些。它只知道流程，不知道那些没写进书里的场景：

- 验收时甲方说"这个功能我之前提过"——是需求遗漏，还是他想多要？
- 监理说"文档不全"——是真的缺，还是流程没留痕？
- 变更来了——是先谈钱，还是先干活？
- 甲方说"整体还行，但细节还要改"——哪些该改，哪些能拖到运维期？

**项目搭子把这些"隐性场景"结构化成了可执行的应变策略**，让AI在遇到这些时刻时，像一个干了15年的老PM一样应对，而不是照本宣科。

## 核心能力 / Core Capabilities

五个关键能力（六阶段流程见上方全景图）：

- **全流程管理**：从启动到收尾，6阶段闭环
- **文档自动生成**：章程、周报、验收报告、复盘报告
- **RAG知识库**：检索历史项目经验，不重复踩坑
- **风险预判**：验收前预判甲方/监理/相关方可能质疑的点，提前准备应变
- **变更控制**：CCB分级审批，小额PM直接批，大额集体审

```
│  ├─ 提示词工程               │
│  │  6阶段SKILL体系           │

│  │  阶段流转 + 工具调用        │
│  └─ 飞书集成                │
│     文档/Base读写（lark-cli） │
└─────────────────────────────┘
```

**AI能做什么、不能做什么：**
- ✅ AI能生成文档模板、分析数据、识别风险、预判验收质疑点
- ✅ AI能检查文档完整性和格式规范
- ❌ AI不能代替PM做决策判断、权衡取舍、甲方签字

## 安装使用 / Installation

### 作为Claude Code技能

将整个目录放入以下任一位置：

**Claude Code技能目录（所有项目可用）：**
```
# Windows
C:\Users\你的用户名\.claude\skills\project-mate\

# macOS / Linux
~/.claude/skills/project-mate/
```

**Agent全局技能目录（跨环境使用）：**
```
# Windows
C:\Users\你的用户名\.agents\skills\project-mate\

# macOS / Linux
~/.agents/skills/project-mate/
```

> 提示：将 `你的用户名` 替换为你电脑上的实际用户名。

### 使用

1. 在Claude Code（或兼容环境）中启动
2. 输入"开始项目""启动项目管理"触发总调度
3. AI按6阶段引导，每个阶段完成确认后进入下一阶段

### 依赖

- Claude Code 或兼容的Agent环境
- 飞书CLI（可选，用于文档/Base读写）
- Chroma（可选，用于知识库RAG检索）
